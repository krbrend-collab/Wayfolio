# Wayfolio Game Night Checklist

## Before players arrive

1. Put the Mac, shared iPad, and player phones on the same local network. Disable a VPN if it prevents local-device connections.
2. Build and install the current Wayfolio app on each phone from the live Xcode project.
3. Double-click `Start Wayfolio Game.command` and keep its Terminal window open.
4. In the launcher, confirm **Central game ready**.
5. In the launcher, scan the **Open the Table Screen** QR code with the iPad, or enter its displayed `/shared` address in iPad Safari. Open **Private DM Screen** only on the host Mac. Keep all DM and story-review pages off the shared display.
6. On the shared screen, select **Enable audio** once and test one quiet sound.

## Join the players

1. On each phone, open the hare profile button and choose **Session**.
2. Select the correct available character.
3. Enter the host address shown on the shared screen and session code `HEMLOCK`, then choose **Join Central Game**.
4. Return to the raised **Live** medallion.
5. Confirm every player is listed as connected on the shared and DM screens.

## Sixty-second table check

1. Publish a short test scene from the private DM screen.
2. Send one player a prompt.
3. Submit one private response from that player's Wayfolio and confirm it appears only for the DM and that player.
4. Submit one public response and confirm it appears on the shared screen.
5. Resolve one digital or physical d20 test on the shared screen.
6. Begin play.

## During play

- Private responses always come from an individual Wayfolio.
- Physical and digital dice are resolved on the shared screen.
- If a phone briefly disconnects, leave the host running; the assigned Wayfolio reconnects automatically.
- If the host restarts, reopen `Start Wayfolio Game.command`. Saved campaign state and device assignments are retained.
- If a player changes devices, create a five-minute transfer code from the old Wayfolio. If the old device is unavailable, release that character from the private DM screen.
- If shared audio becomes disruptive, use **Stop all audio** on the private DM screen.

## If something goes wrong

- Shared screen cannot connect: confirm the Terminal host is still open and all devices are on the same network.
- Phone cannot join: verify the displayed host address, `HEMLOCK` code, selected character, and iOS local-network permission.
- Character is already assigned: reconnect from the assigned phone, use a transfer code, or release the assignment privately.
- Roll appears stuck: check the shared-screen roll panel; a reconnecting Wayfolio will continue showing that its table roll is pending.
- Action is rejected: dismiss the notice on the Live page, wait for the current DM review or roll to finish, and submit again.
